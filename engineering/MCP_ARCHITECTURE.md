# MCP_ARCHITECTURE.md — تصميم التحكم الخارجي عبر MCP

**تاريخ:** 2026-11-17  
**الفرع:** engineering/audit-phase1

## المبدأ الأساسي

MCP ليس بديلًا عن التطبيق. رُسوخ يعمل كاملًا دون الإنترنت. ChatGPT واجهة تحكم إضافية فقط.

لا يمكن لـ ChatGPT الوصول مباشرة إلى ملفات تطبيق iOS بسبب عزل النظام. لذلك نحتاج خادم MCP بعيد مع مصادقة.

## البنية المقترحة

```
ChatGPT
    ↓ HTTPS + MCP
Remote MCP Server (مستقل)
    ↓ Authentication & Authorization (أقل صلاحية)
Tool Router
    ↓
Rusukh Application Services (محلي أو متصل)
    ↓
Local Database / Optional Sync
    ↓
Verified Result
```

### أنماط الاتصال
- **متصل:** تنفيذ فوري عبر الخادم.
- **محلي:** التطبيق يعمل بالكامل. لا يتطلب MCP.
- **غير متصل:** تسجيل أوامر مؤجلة عند الملاءمة، ثم معالجتها عند العودة مع قواعد التعارض.
- العمليات التي تتطلب وجود التطبيق مفتوحًا تُوضح صراحة.

## الأدوات الأولى (مستخرجة من التطبيق الحالي)

### قراءة (أولوية)
- list_notes, get_note, search_notes
- list_flashcards, get_due_cards
- get_learning_progress, get_daily_summary
- get_app_status, get_storage_usage

### كتابة (تتطلب صلاحية وتأكيد للخطيرة)
- create_note, update_note
- create_flashcard, generate_flashcards
- review_flashcard
- create_quiz

### إدارة
- get_app_settings, update_app_settings (محدود)
- list_modules

الأدوات الكاملة ستُوثّق بعد تحليل الخدمات الفعلية.

## الأمن

- مصادقة آمنة (لا مفاتيح مكشوفة).
- صلاحيات دقيقة لكل أداة.
- أدوات القراءة منفصلة عن الكتابة.
- العمليات الخطيرة (حذف جماعي، تغيير إعدادات) تتطلب موافقة صريحة.
- سجل تدقيق.
- التحقق من المدخلات ومنع الحقن.
- حدود طلبات.
- إمكانية إلغاء الصلاحيات في أي وقت.

## الخطوة التالية
1. تحديد مستودع الأدوات الأولى من الخدمات الحالية.
2. تصميم واجهة Tool مجردة في RusukhCore.
3. بناء MCP Server مستقل يستدعي هذه الواجهة.
4. اختبار الأدوات واحدة واحدة مع إثبات النتيجة.

لا يبدأ التنفيذ قبل توثيق الواجهات والصلاحيات في هذا الملف.
