الحفظ في الجلسة مستقل عن مادة الدراسة. التوليد لا ينشئ بطاقات ولا يحفظ ملاحظة تلقائيًا؛ زر «مراجعة الأسئلة في المحرر» ما زال خطوة صريحة. «تجاهل جلسة المساعد» يتطلب اختيارًا صريحًا في حوار، ويمسح مصدر المساعد ونتيجته فقط.

## حدود الحفظ والاسترداد

- يحفظ التطبيق لقطة المصدر وعنوانه والمرجع الأصلي `{id, createdAt, updatedAt}` والنتيجة المتحققة حرفيًا؛ لا يحفظ نموذج GGUF أو worker.
- قراءة التخزين تتحقق من version، الأنواع، حدود الأطوال، المرجع، ومطابقة نتيجة المصدر. قيمة تالفة تبقى في التخزين، ويُمنع الكتابة فوقها مع زر إعادة المحاولة.
- فشل الكتابة يبقي أحدث قيمة في الذاكرة ويظهر تحذيرًا. لا ضمان لبقاء تعديل غير محفوظ إذا أغلق النظام العملية قبل نجاح SQLite؛ واجهة الحفظ لا تدّعي خلاف ذلك.
- الكتابات مرتبة وتلتقط JSON غير قابل لتغيير المدخل لاحقًا. الكتابة القديمة لا تعيد نصًا قديمًا في الواجهة ولا تتجاوز تجاهلًا أحدث. تغيير اتصال قاعدة البيانات يمنع تنفيذ الكتابات المؤجلة على الاتصال الجديد.
- حد المصدر المخزّن مليون حرف حتى لا تضيع الملاحظات الطويلة قبل اختيار مقطع؛ حد التوليد ما زال 1600. حد JSON يشمل أسوأ توسع للمحارف المهروبة. نتيجة المخزن تمر بنفس تحقق الجسر.
- تُحتفظ النتيجة المكتملة التي وصلت إلى التطبيق. رسالة قديمة وصلت بعد إبطال الطلب بسبب الخلفية أو خطأ WebView تظل مرفوضة؛ لا يمكن الادعاء باسترداد مخرجات لم تصل أصلًا إلى الحاضن.
- المصدر المحذوف أو المعدل أو الذي أُعيد استعمال معرّفه مع زمن إنشاء آخر لا يُربط تلقائيًا بملاحظة حالية. نص اللقطة والمرجع القديم يبقيان في جسم المسودة. يمرر `onDraft.sourceNoteId` فقط إذا بقي المرجع ومراجعته ومحتواه مناسبين. هذا تحسين جزئي لـ A008/S006؛ ليس نظام provenance كاملًا ولا تحققًا من بصمة النموذج.
- على App استعمال `useAIStudySession(db)` دائمًا وتمرير `session`، وإدخال المفتاح والحالة الحية في حاجز استبدال المكتبة. ملفات App ليست ضمن ملكية هذه المهمة؛ مسؤول الدمج يتولى ذلك ويختبره.

## الأدلة الفعلية

- الأساس: 15 Jest + 28 عقود/runtime ناجحة.
- قبل الإصلاح: ستة فحوص UI/bridge جديدة فشلت، وفحصا runtime/عربية فشلا. السجلات `red-ui.log` و`red-runtime.log`.
- بعد الإصلاح: 38 Jest في ثلاثة ملفات، و32 عقود/runtime، وTypeScript ناجحة. إعادة البناء والتصدير النهائية على مسؤول الدمج.
- تجميع تعبيرات Unicode بالحزمة المحلية `hermes-compiler` نجح. هذا تجميع فقط؛ ليس تشغيلًا على iPhone.
- mock التخزين لا يختبر SQLite الفعلي، وmock WebView لا يختبر WKWebView، وStubWllama لا يجري استدلالًا. لا تضاف هذه الأعداد إلى تجارب الاستدلال الحقيقي.
- الملفات والبصمات والأعداد في `verification.json`. لا توجد صور جهاز في هذه الجولة.

## R004: ربط المصدر بالمحرك المضمّن

أُعيد بناء `engine.generated.ts` و`engine-manifest.json` محليًا بواسطة `npm run build --prefix ai-lab` مع الاعتماديات المثبتة، دون تنزيل جديد. يتضمن manifest الآن بصمات جميع وحدات المصدر المحلية الداخلة في bundle، وbuild.mjs وpackage/lock والتراخيص، وبصمة ملف generated كاملًا بالإضافة إلى HTML وWASM وworker. الملف المولد 21,861,949 بايت؛ HTML الأصلي 21,853,882 بايت. البصمات الكاملة في `build-integrity-after-rebuild.json`.

يبدأ `verify-release.cjs` الآن بفحص مستقل `verify-ai-build.cjs` قبل تشغيل الاختبارات المكلفة. يستخرج HTML بواسطة JSON.parse دون تنفيذ JavaScript، ويقارن البصمات والأحجام ومدخلات البناء الحالية. تغيّر entry أو contracts أو build أو lock بعد البناء يوقف الإصدار حتى إعادة البناء؛ لا يكفي تطابق HTML قديم مع manifest قديم.

اختبارات `tests/ai-build-integrity.test.cjs` الخمسة نجحت: المخرجات الحقيقية، تغيير كل مدخل إلزامي، تغيير generated، عدم تطابق HTML، وmanifest ناقص/مسار خارج المشروع. `build-integrity-before-rebuild.log` يسجل رفض manifest القديم، و`ai-build.log` و`build-integrity-tests.log` يسجلان البناء والتحقق. لم تُشغّل اختبارات المشروع الشاملة أو أي بناء بعيد في هذه الخطوة.

هذا تحقق اتساق للمخرجات ومدخلات البناء المحفوظة؛ ليس توقيعًا ضد تعديل متعمد للمصدر والـmanifest معًا، ولا تحققًا من ملف نموذج المستخدم، ولا إثباتًا لتشغيل WASM على iPhone.

يبقى مدير تنزيل نماذج دائم ومتحقق من البصمة غير منفذ. التحميل اليدوي، حدود الذاكرة، جودة العربية، Files/iCloud، VoiceOver، والخلفية الفعلية تحتاج تجربة جهاز. التبديل بين المصادر يعيد استعمال نموذج جاهز داخل الشاشة فقط؛ مغادرة الشاشة أو تفريغ المحرك يتطلب اختيار ملف النموذج مجددًا.
