# تحقق مسارات البيانات

- `d002-original-reproduced.log`: إعادة إثبات الحد الأصلي على 9 ملاحظات عربية محفوظة. حجم JSON هو 18,001,085 بايت؛ هذا ليس قياسًا لذاكرة iPhone.
- `card-update-red.log` / `card-update-green.log`: واجهة تعديل البطاقة، مع بقاء مواعيدها وملاحظة الأصل والسجل.
- `database-snapshot-red.log` / `database-snapshot-green.log`: إنشاء نسخة SQLite مستقلة من قاعدة WAL بما فيها المسودة والتفضيلات ونقاط الرجوع؛ مصدر الاختبار ووجهته على قرص Node SQLite، وواجهة Expo موائمة.
- `bootstrap-and-card-green.log`: يتضمن فشل تهيئة SQL ثم إعادة الفتح الآمنة، دون حذف بيانات قديمة أو إعادة إدخال الأمثلة.
- `database-snapshot-typecheck.log`: فحص TypeScript مستقل، ورمز الخروج 0.
- `data-targeted-green.log`: 31 اختبارًا ناجحًا، صفر فشل، للتهيئة والتخزين ونقاط الرجوع وتعديل البطاقة والإنقاذ.
- `data-result.json`: الواجهات البرمجية، الحدود، النتيجة وبصمات ملفات هذا العمل.

D002 **جزئي ويبقى مفتوحًا**: حد JSON البالغ 15 MiB باقٍ. الإنقاذ الجديد بصيغة SQLite له سقف 512 MiB ويحتاج مساحة قرص للنسخة. لا توجد استعادة SQLite داخل التطبيق؛ لا يجوز وصفه كنسخة يمكن استعادتها بزر الاستيراد الحالي. يضم meta والمسودات ولا يضم ملفات الصور والصوت. لم تُضف قيود كتابة أو حد يوقف المراجعات.

المصدر المثبت محليًا للواجهة البرمجية هو `node_modules/expo-sqlite/src/SQLiteDatabase.ts`: تعيد serializeAsync مصفوفة Uint8Array، وتنشئ deserializeDatabaseAsync قاعدة في الذاكرة، وتنسخ backupDatabaseAsync بين قاعدتين. اخترنا الأخيرة لتجنب تحميل ملف قاعدة البيانات كاملًا في JavaScript. اختبار iPhone وExpo Go الأصلي باقٍ.
