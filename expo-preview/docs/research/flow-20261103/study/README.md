واجهة المكوّن:

```tsx
<StudyQuiz p={p} cards={cards} notes={notes}
  onClose={close}
  onOpenNote={(note) => openSource(note)}
  onAddMaterial={addMaterial}
  onNewNote={newNote} />
```

المكوّن يحتوي ScrollView. أبقه mounted عند عرض المصدر كي لا تبدأ جلسة جديدة. إغلاق التدريب أو الضغط على «جلسة جديدة» ينهي الاحتفاظ بنتيجة الجلسة الحالية؛ النتائج ليست سجلًا دائمًا. لا يكتب المكوّن إلى التخزين أو يغيّر مواعيد المراجعة.

`makePracticeSession` يأخذ نسخة مستقلة من نصوص البطاقات، يزيل تكرار الهوية وتكرار السؤال/الإجابة المطابقين بعد تطبيع المسافات والحالة، ويأخذ حتى 8 بطاقات صالحة. الأسئلة المختلفة ذات الإجابة المشتركة تبقى. حد غير صالح أو غير موجب يعطي عينة فارغة. عشوائية Fisher–Yates قابلة للحقن في اختبارات المنطق. اختيار جديد يحدث عند بدء جلسة جديدة فقط. قفل متزامن بالمرجع يمنع احتساب ضغطتي التقييم قبل إعادة العرض، ويمنع callback قديم من تقييم السؤال التالي.

قواعد Q/A المعلنة: تبدأ الكتلة بـ `س:` أو `Q:` ثم `ج:` أو `A:`. تمتد الأسطر والفقرات حتى السؤال التالي أو فاصل `---`/`***`/`___` أو عنوان Markdown أو سطر اقتباس `>` أو سياج شيفرة أو بيانات المصدر المحجوزة. الأسوار تُعامل كمقاطع مقتبسة، ولا تُستخرج منها بطاقات؛ لا تُفسّر أسطر `Q:` داخلها. من بيانات الحدود: `الشاهد:`، `مرجع السؤال:`، `مقاطع المصدر:`، `المصدر:`، `النموذج:`، `رابط الفيديو:`، `نوع التفريغ:`، `النص الذي استُخدم:`، `التفريغ الأصلي`. لذلك يجب فصل النثر اللاحق غير التابع للإجابة بفاصل صريح. لا يدّعي المحلل فهم حدود المعنى تلقائيًا.

في YouTube تُحفظ فقرات النص، وتُربط كل أسطر السؤال والإجابة بالمقاطع المشاركة. يبقى رابط السؤال عند مقطعه الأول، ويغطي `startMs/endMs` كل المقاطع المشاركة حتى إذا كانت التوقيتات خارج الترتيب. يبقى التفريغ الأصلي كما هو في الاقتباس ولا يُعاد استخراج بطاقاته. تشمل الأدلة SRT وVTT ونصًا عاديًا، وبيانات NOTE مستبعدة، واستمرار الإجابة عبر عدة مقاطع.
