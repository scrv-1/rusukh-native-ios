## بوابة Expo Go: افحصها قبل الوعد برابط
عند قراءة وثائق Expo الرسمية في 3 نوفمبر 2026: صفحة version mismatch تقول إن App Store Expo Go يتوقف عند SDK54، وإن SDK55+ على iPhone يحتاج مسارًا متوافقًا مثل eas go/TestFlight بعضوية Apple. المشروع SDK58. لم نتحقق من إصدار العميل المثبت على هاتف فهد. لا تقل إن تحديث App Store أو Metro وحده يحل ذلك.
تحقق من الإصدار والتوزيع الموجود فعلًا ومن إرشادات Expo الحالية. إن كان العميل غير متوافق، اعرض الخيارات القابلة للتنفيذ والتكلفة والآثار؛ يمكن اختبار مسار توافق منفصل مع الحفاظ على الميزات والبيانات، لكن لا تخفض SDK عميانيًا ولا تشتري عضوية. لا تصف Preview Web أو Simulator كتطبيق iPhone.

عند توفر عميل متوافق ومضيف مصرح:
- افحص cwd/branch/HEAD وgit status وعمليات ومنافذ الخادم. لا توقف عملية لا تعرف مالكها ولا تمس تعديلات مستخدم.
- اقرأ مساعدة Expo المثبت والـlauncher الحالي. أعد استخدام جلسة دخول آمنة صالحة؛ الأسرار خارج المحادثة والسجلات.
- شغّل --go والنفق وفق CLI الحالي على منفذ خالٍ، بمهلة موثوقة لا تتجاوز ساعة لهذه التجربة؛ لا تغيّر مهلة خمول Codespace ولا تعد بعمل دائم.
- افحص manifest لمنصة ios ثم نزّل launchAsset/bundle المحدد فيه: HTTP status وحجم غير صفري وبصمة، دون طباعة الحزمة؛ سجّل فرع البناء والإصدار ووقت الفحص.
- سلّم exp:// الحالي أو رابط Expo الفعلي، وPID والمنفذ والسجل ووقت الانتهاء بتوقيت الرياض. راجع أخطاء Metro. الرابط السابق في الملاحظات غير صالح كدليل جديد.
- اختبار الهاتف منفصل: أول فتح، ملاحظة وبطاقة وكويز، استئناف، PDF، إذن صوت مرفوض ومقبول، نسخ واستعادة، خط كبير وVoiceOver. لا تدّع اجتيازه حتى يوجد دليل من الجهاز.

## طريقة التنفيذ مع تقليل التوكن
1. اقرأ هذا الملف وتعليمات AGENTS الفعلية إن وجدت وpackage scripts. افحص الحالة الحية مرة واحدة واحفظ fingerprint. استخدم الملفات الدائمة للتقدم؛ لا تعِد قراءة الخزنة أو سجل المحادثات كله.
2. أنشئ أو حدّث مصدرًا واحدًا لـGOALS/STATUS: goal → implementation → test → evidence → limitation → next action. حالة قصيرة عند الاستئناف، وتفاصيل عند الطلب.
3. ابحث بـrg عن المسار المطلوب، واقرأ المقطع واختباره؛ اجمع القراءات المستقلة. لا تحمل engine.generated.ts أو lockfiles أو logs كاملة في السياق: افحص حجمها/بصمتها والمدخلات والمخرجات برمجيًا.
4. استخدم مخرجات أدوات منتقاة؛ logs كاملة في ملفات، والرد ملخص exit code والعدد وسبب الفشل. حدّث diff سياق صغيرًا عند قرار أو تغير مهم فقط. لا تدّع نسبة توفير توكن لم تُقَس.
5. لا توقف العمل لأن التقرير صار طويلًا؛ ضغط السياق لا يعني إسقاط هدف أو تجاوز اختبار. وفر في التكرار والتقارير، لا في الإصلاح أو الدليل.
6. لكل عيب: إثبات قابل للتكرار → إصلاح السبب → اختبار انحسار مناسب → فحص جارٍ للمتأثر. لا تختلق اختبارات لكل تغيير شكلي. لا تغيّر الاختبارات لإخفاء مشكلة؛ أي تغيير للعقد له سبب موثق.
7. محامي الشيطان وظيفة نقدية: حاول كسر الفرضية بأمثلة عملية (double tap، callbacks قديمة، قتل التطبيق، فشل كتابة، مصدر محذوف/معدل، مكتبة ضخمة، ملف تالف، تعارض فرع، اختلاف SDK). النقد الذاتي ليس مراجعة مستقلة، ولا تعطِ درجات 9/10 كدليل نجاح.
8. ابحث رسميًا لفجوة محددة أو اعتماد متغير، واستخدم المجتمع لاستخراج فرضيات قابلة للاختبار. لا تجمع عشرات الروابط لمجرد العدد ولا تضف MCP أو حزمة دون منفعة مباشرة.
9. نفّذ بترتيب الأثر: سلامة البيانات وتوافق المعاينة → تجميع الفروع → رحلة الدراسة والكويز الحقيقي والمنشأ → بقية الأهداف الممكنة → الجهاز والتسليم. حافظ على SwiftUI ولا تعِد بناء المشروع من الصفر بلا مبرر.
10. عند عائق فعلي: جرّب بديلًا مصرحًا عمليًا، ثم أكمل العمل المستقل. اسأل سؤالًا واحدًا محددًا فقط إذا كان القرار أو الدخول أو النفقة لا يمكن تجاوزه ضمن التفويض. دوّن الخطوة التالية التي تزيل العائق. لا تعد بمواصلة خفية بعد انتهاء المهمة.

## فحوص التسليم
من expo-preview، بعد تثبيت lock:
npm test
npm run test:ui
npm run typecheck
npx expo install --check
npx expo-doctor
node --test ai-lab/test.mjs ai-lab/engine-runtime.test.mjs
node scripts/verify-ai-build.cjs
node scripts/verify-release.cjs

اقرأ scripts الفعلية أولًا؛ verify-release يشمل عدة أوامر أعلاه فلا تعدها مرتين ولا تكررها بلا تغير أو فشل. ai-lab له package-lock مستقل وnpm ci خاص. الموارد المولدة تُبنى من مدخلاتها وتُتحقق بصماتها. اجعل كود الاختبار مطابقًا للـcommit الذي ترفعه. SwiftUI يتطلب بوابة macOS/Xcode المناسبة؛ نجاح Linux لا يثبتها.

التسليم النهائي لفهد بالعربية المباشرة: ما أصلح، ما اختبر وما بقي، روابط commit وPR وأدلة، SHA ونسخة ومعاينة حية إن أمكن، وقائمة جهاز قصيرة. لا تقل «انتهى من الألف للياء» أو «100%» مع بنود محجوبة. اذكر الفارق بين تجهيز البرومبت، قبول مهمة كودكس، اكتمالها، وفتح التطبيق على الهاتف.
