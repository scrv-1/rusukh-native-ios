# دمج FSRS-6 واختبارات الحماية

الفرع: `work/fsrs-integration-20261101`. اعتماد MIT: [swift-fsrs](https://github.com/open-spaced-repetition/swift-fsrs/tree/4fbaf20184d62f82a9f44f343337c61a2c5483e9)، مثبت عند `4fbaf20184d62f82a9f44f343337c61a2c5483e9` في SwiftPM وXcodeGen وPackage.resolved. نص الترخيص مورد في التطبيق، ووجوده الفعلي في حزم Xcode وxtool والمحاكي شرط CI.

## سياسة البيانات

البطاقات الجديدة فقط تستخدم FSRS-6 بأوزان canonical ذات 21 عنصرًا، وretention قدره 0.9، وخطوتي تعلم 1m و10m، وإعادة تعلم 10m، دون fuzz. لا تدريب شخصي أو ضمان لنسبة تذكر فعلية. البطاقات القديمة تحتفظ بمواعيدها وحالتها والمجدول السابق. لا يُختلق تاريخ تعلم ولا يُعاد حسابه تلقائيًا. عزل هذا التغيير عن GRDB يمنع ترحيل التخزين بالكامل في الدفعة نفسها.

ملفات v1 تبقى مقروءة. وجود FSRS يرفع النسخة إلى v2 لكي يرفضها التطبيق الأقدم بدل فقدان الحالة بصمت. تُحفظ هوية الخوارزمية والمعلمات وحالة الذاكرة. يُرفض الاستيراد عند فقدان الحقول أو null أو معلمات غير معروفة أو تعارض العدادات أو خطوات تعلم غير صالحة. أقصى فترة 36500 يوم، ويُضبط الموعد وعدد الأيام معًا عند السقف. الرجوع للتطبيق الأقدم يحتاج نسخة v1 سابقة؛ لا تخفيض صامت لـv2.

## التحقق

قبل إصلاح الحالات الحدية: 9 اختبارات خرجت برمز 1 و5 إخفاقات. قبلت النسخة الأولى حذف خطوة التعلم وnull، وعدّادًا متناقضًا وخطوة إعادة تعلم خارج المجال؛ كما رمت invalidState عند السقف. بعد الإصلاح نجح 50 اختبارًا على Linux مع Swift 6.4.2، بما فيها سلسلة مرجعية من 13 مراجعة مع تصدير واستيراد بعد كل خطوة. هذا لا يمثل اختبار iPhone.

أضيفت أربع اختبارات للتطبيق الفعلي: حفظ الحالة ومراجعتها وإعادة فتحها، الحفاظ على الجدول القديم ومرفقه، رفض JSON ناقص دون تغيير بايتات المخزن، وفشل كتابة حقيقي دون نشر ملاحظة غير محفوظة. نجح 57 اختبار محرك على Mac في Run 17، بما فيها وحدات FSRS التسع. لم تبدأ اختبارات التطبيق والواجهة بسبب خطأ تغليف xtool؛ أُصلح وأعيد التشغيل في Run 18.

Run 16 أثبت نجاح 46 وحدة و9 اختبارات تطبيق/واجهة وبناء المحاكي والجهاز وxtool، لكنه فشل في حاجز تحذير الصوت. نقلت الدفعة التالية تهيئة المسجل والمشغّل وبدءهما إلى طابور الجلسة أيضًا، وأضافت اختباري وحدة واختبار متحكم للإغلاق أثناء التهيئة. سجل الدليل في `run-16-audio-warning-excerpt.txt`.

## المتبقي

تحويل البطاقات القديمة إلى FSRS يحتاج خيارًا صريحًا وسياسة لإعادة تشغيل التاريخ ومقارنة المواعيد ونسخة رجوع؛ لم يُفعّل. تحسن التذكر يحتاج بيانات مستخدم وتقييمًا، ولا تثبته اختبارات المعادلات. GRDB وOCR والتفريغ الصوتي والبحث الدلالي والاختبارات البصرية ما زالت بنودًا منفصلة في سجل التنفيذ.

## خطأ التغليف المكتشف في Run 17

المصدر `2bd00c312ece278ae2dac19dc5cce31984f73781`: نجح Xcode للمحاكي والجهاز والإطلاق والتصوير، ثم فشل xtool برسالة duplicate rule للترخيص. أُعيد إنتاج الخطأ محليًا بواسطة `RUSUKH_XTOOL=1 swift package describe` (exit 1). تعريف مصادر App صراحة ضم النص أيضًا كمصدر، بينما `.copy` يعرّفه موردًا. حُذف تعريف sources الصريح، وبقي المورد والاستثناءات. خرج وصف SwiftPM برمز 0 وتحققت مطابقة ملفات Swift الـ21 المقصودة ومورد واحد. أُضيف الفحص المبكر إلى Actions، ثم نجحت اختبارات Linux الـ52 مرة أخرى. هذا تحقق تعريف الحزمة؛ نجاح تغليفها الفعلي ينتظر Run 18.
